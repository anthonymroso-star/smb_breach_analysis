# Incident Response Report: Brute-Force Attack Analysis (NIST SP 800-61 r2)

## 1. Incident Summary
* **Who**: External malicious threat actor originating from source IP address `172.16.0.100`.
* **What**: Automated SMB2 brute-force credential spray and privileged account takeover.
* **When**: Detected on 2026-08-08 between 07:44:33 and 07:50:53 BST.
* **Where**: Target asset server `targetserver` (Internal IP: `192.168.10.10`) running an exposed Samba file-sharing interface.
* **Why**: To bypass authentication barriers, establish a privileged root foothold, and exfiltrate sensitive text-based data assets.

## 2. Detection & Telemetry Analysis
The attack milestone metrics were captured partially by the active Wazuh agent monitoring `/var/log/auth.log`, with critical context gaps reconstructed via packet parsing.

### Key Telemetry Triggers:
* **Wazuh Rule ID**: 17101 (Successful login during non-business hours)
* **MITRE ATT&CK Mapping**: T1078 (Valid Accounts) / T1110.001 (Brute Force: Password Guessing)
* **Forensic Payload Signature (SIEM Layer)**:
```json
"full_log": "2026-08-08T07:44:36.170577+01:00 targetserver smbd: pam_unix(samba:session): session opened for user dummy_attacker(uid=1001) by (uid=0)"
```

### Wire Reconstruction (`smb_breach_sanitized.pcapng`):
Because default server optimisation (`log level = 1`) suppressed individual connection errors on the SIEM dashboard, a custom Python script extracted the missing transport-layer context directly from the 64-byte SMB2 application headers at fixed byte offsets:
* **NT Status Offset [8:12]**: Captured exactly six sequential `0xc000006d` (`STATUS_LOGON_FAILURE`) tokens immediately preceding a successful authentication loop. This programmatically confirms machine-driven dictionary scanning.
* **Command ID Offset [12:14]**: Tracked 21 successful `0x0001` (Session Setup) and `0x0005` (Create Response) tokens, proving active directory interaction.
* **Exfiltrated Asset Strings**: Extracted literal printable UTF-8 filenames opened by the unmasked IP: `9xnetwork_map.txt`, `9xpayroll_records.txt`, and `9xpasswords.txt`.

## 3. Containment & Remediation Actions
To mitigate the threat vectors immediately, a three-phase playbook execution was carried out:
* **Host Isolation/Hardening**: Revoked compromised credentials across the core OS layer and individual Samba database vaults, forcing an immediate password reset on the `dummy_attacker` profile.
* **Telemetry Validation**: Modified `/etc/samba/smb.conf` to adjust application logging parameters to `log level = 2`, ensuring future external connection socket handshakes print natively to disk for SIEM ingestion.
* **Active Edge Blocking**: Restarted active file-sharing service daemons to instantly drop all active attacker handles and implement the hardened configuration baseline.
